# RCA — avero.live ERR_SSL_PROTOCOL_ERROR (custom domain)

## Deployment
- Deployment: `avero-pos-system` (id 8e899090-52e7-47de-8f32-11010bd219a4)
- Active run: 33ac97e4-8449-45bf-ba10-0202a069dd84 (status success)
- Template: fastapi_react_mongo_shadcn_base_image · frontend_type: **cloudflare**
- Live platform URL: https://avero-pos-system.emergent.host (healthy)

## Symptom
`https://avero.live` on mobile Chrome → "This site can't provide a secure connection — avero.live sent an invalid response. ERR_SSL_PROTOCOL_ERROR". Preview/emergent.host URLs work.

## Evidence (from list_domains + check_domain_status + describe_deployment_state)
| Hostname | verified | ssl_status | DNS linked |
|---|---|---|---|
| avero.live (apex) | true | active | true |
| www.avero.live | false | pending_validation (http) | true |

- Apex `avero.live`: verified=true, ssl_status=**active**, A-record linked=true → platform side fully provisioned; cert issued.
- `www.avero.live`: verified=**false**, ssl_status=**pending_validation** (validation_method=http), cf_custom_hostname_id=a790e094-fd62-4642-a00a-3f9be7b3b92c → **no certificate issued for the www hostname.**

## Root cause
`www.avero.live` has NO active SSL certificate — its Cloudflare custom-hostname validation is still pending. Any HTTPS request that lands on `www.avero.live` hits the edge with no valid cert for that name and fails with ERR_SSL_PROTOCOL_ERROR. Mobile Chrome frequently auto-prepends `www.` / follows a www redirect, so a user typing `avero.live` can be routed to the un-certified `www` hostname. The apex hostname itself is correctly certified and active; if the apex specifically still errors for the user it is client/DNS propagation or cached-cert on the device, not a platform-side cert gap.

HTTP-based cert validation for `www` cannot complete until the `www` DNS record correctly points at (and is proxied through) the Cloudflare edge so the validation token is reachable over HTTP.

## Fix — user actions at their DNS provider
1. In Deployment Panel → Domains, open `www.avero.live` and copy the **exact** DNS record Emergent displays for it (a CNAME to the platform/Cloudflare SaaS target). Do NOT invent the target — use the value shown in the panel verbatim.
2. At the DNS provider for avero.live, create/correct that record for the `www` host (typically `CNAME www → <target shown in panel>`). Ensure it is proxied/pointing to the platform edge, not to any origin IP.
3. Keep the apex `avero.live` record exactly as the panel shows it (it is already verified + active — do not change it).
4. Wait for DNS propagation and for `www` ssl_status to move from `pending_validation` → `active` (can take up to a few hours). Re-check in Deployment Panel → Domains.
5. If the apex `avero.live` itself still shows the SSL error on the device after this, it is local DNS/cert caching: retest in incognito / another network / after flushing DNS, since the platform reports the apex cert as active.

## Platform side
Nothing to change — apex cert is active and the app/run is healthy. `www` cert will auto-issue once its DNS validation record is reachable. No redeploy required (domain/SSL provisioning is independent of the deploy pipeline).
